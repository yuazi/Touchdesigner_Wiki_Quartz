## Introduction

### Three Paradigms of Learning
![[Lec11_Pg009_Three_Paradigms_Of_Learning.png]]


| Paradigm                   | How it learns                                         | Data                          |
| -------------------------- | ----------------------------------------------------- | ----------------------------- |
| **Supervised Learning**    | Learn a mapping from input to output                  | Ground truth labels available |
| **Unsupervised Learning**  | Learn the structure of a dataset                      | No ground truth               |
| **Reinforcement Learning** | Data revealed through interacting with an environment | Learn how to act              |

Informally:

- **SL**: "This is a cat."
- **UL**: "These two images look similar."
- **RL**: "This cat likes to be scratched behind the ears." _(discovered through interaction)_

### The RL Problem
![[Lec11_Pg013_The_Rl_Problem.png]]


> **Reinforcement learning** is learning to solve sequential decision problems via repeated interaction with an environment (trial and error).

Three questions to answer:

1. What is a sequential decision problem? → **MDP**
2. What does it mean to "solve" it? → Maximise total reward
3. What is learning by interaction? → **TD / Policy Gradient**

### The Agent–Environment Loop
![[Lec11_Pg015_The_Agent_Environment_Loop.png]]


```
     +-----------------------------------+
     |            Agent                  |
     |         Policy π(a|s)             |
     +----------------+------------------+
                      | action (At)
                      v
     +-----------------------------------+
     |          Environment              |
     |   state (St)    reward (Rt)       |
     +-----------------------------------+
```

At each timestep $t$:

1. Agent observes state $s_t$
2. Agent selects action $a_t \sim \pi(\cdot|s_t)$
3. Environment transitions to $s_{t+1}$ and emits reward $r_{t+1}$
4. Agent uses $(s_t, a_t, r_{t+1}, s_{t+1})$ to update its policy

## Markov Decision Process (MDP)

### Formal Definition
![[Lec11_Pg023_Formal_Definition.png]]


An MDP is the tuple $(S, A, R, T, \mu)$:

| Symbol                                  | Meaning                                                           |
| --------------------------------------- | ----------------------------------------------------------------- |
| $S$                                     | Finite set of states (with terminal subset $\bar{S} \subseteq S$) |
| $A$                                     | Finite set of actions                                             |
| $R: S \times A \times S \to \mathbb{R}$ | Reward function                                                   |
| $T: S \times A \times S \to [0,1]$      | State-transition function $p(s' \mid s,a)$                        |
| $\mu: S \to [0,1]$                      | Initial state distribution                                        |

The **Markov property**: the future depends only on the current state, not history:
$$p(s_{t+1}|s_t, a_t, s_{t-1}, a_{t-1}, \ldots) = p(s_{t+1}|s_t, a_t)$$

### Expected Discounted Return
![[Lec11_Pg024_Expected_Discounted_Return.png]]


The goal is to learn a policy $\pi$ that maximises the **expected discounted return**:

$$\mathbb{E}_\pi[G_t] = \mathbb{E}_\pi\!\left[\sum_{k=0}^{\infty} \gamma^k r_{t+k+1}\right]$$

- $\gamma \to 0$: **myopic** — only cares about immediate reward
- $\gamma \to 1$: **far-sighted** — weights all future rewards nearly equally

> **Example**: Rewards of $1, 1, 1, \ldots$ forever. With $\gamma = 0.9$: $G = \frac{1}{1-0.9} = 10$. Without discounting $(\gamma=1)$ the sum diverges.

### Value Functions
![[Lec11_Pg030_Value_Functions.png]]


**State-value function**: $V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]$

**Optimal**: $V^*(s) = \max_\pi V^\pi(s)$

**Action-value function**: $Q^\pi(s, a) = \mathbb{E}_\pi[G_t \mid S_t = s, A_t = a]$

**Optimal**: $Q^*(s, a) = \max_\pi Q^\pi(s, a)$

**Key relationships**:
$$V^\pi(s) = \sum_a \pi(a|s)\, Q^\pi(s, a) \qquad V^*(s) = \max_a Q^*(s, a)$$

**Optimal policy** derived from $Q^*$:
$$\pi^*(a|s) = \begin{cases} 1 & \text{if } a = \arg\max_{a'} Q^*(s, a') \\ 0 & \text{otherwise} \end{cases}$$

Or via one-step look-ahead using $V^*$:
$$\pi^*(a|s) = \begin{cases} 1 & a = \arg\max_{a'}\!\left[\sum_{s'} p(s'|s,a')\bigl(r(s,a',s') + \gamma V^*(s')\bigr)\right] \\ 0 & \text{otherwise}\end{cases}$$

### Bellman Equation
![[Lec11_Pg038_Bellman_Equation.png]]


The return decomposes recursively: $G_t = r_{t+1} + \gamma G_{t+1}$. Taking expectations:

$$\boxed{V^\pi(s) = \sum_a \pi(a|s) \sum_{s'} p(s'|s,a)\!\left[r(s,a,s') + \gamma V^\pi(s')\right]}$$

$$Q^\pi(s, a) = \sum_{s'} p(s'|s,a)\!\left(r(s,a,s') + \gamma \sum_{a'} \pi(a'|s') Q^\pi(s',a')\right)$$

We can solve for $V^\pi$ iteratively:
$$V^\pi_{[k+1]}(s) = \sum_a \pi(a|s) \sum_{s'} p(s'|s,a)\!\left[r(s,a,s') + \gamma V^\pi_{[k]}(s')\right]$$

## Dynamic Programming
![[Lec11_Pg043_Dynamic_Programming.png]]


When the full model $(T, R)$ is known, we can find the optimal policy exactly.

### Methods Overview
![[Lec11_Pg042_Methods_Overview.png]]


| Method                  | Requires model? | How it works                            |
| ----------------------- | --------------- | --------------------------------------- |
| **Dynamic Programming** | Yes             | Iterate over all states using the model |
| **Monte-Carlo**         | No              | Full trajectory rollouts                |
| **Temporal-Difference** | No              | Bootstrap from visited states           |

### Policy Iteration
![[Lec11_Pg044_Policy_Iteration.png]]


1. **Policy Evaluation**: compute $V^\pi$ for current $\pi$
2. **Policy Improvement**: update $\pi$ greedily w.r.t. $V^\pi$

$$\pi^0 \xrightarrow{\text{eval}} V^{\pi^0} \xrightarrow{\text{improve}} \pi^1 \to \ldots \to V^* \to \pi^*$$

Guaranteed to converge to $\pi^*$ in finite iterations.

### Value Iteration
![[Lec11_Pg045_Value_Iteration.png]]


Apply the **Bellman optimality equation** as an update:

$$V_{k+1}(s) \leftarrow \max_{a \in A} \sum_{s' \in S} p(s'|s,a)\!\left[r(s,a,s') + \gamma V_k(s')\right], \quad \forall s \in S$$

**Algorithm:**

```
Initialize V(s) = 0 for all s in S
repeat:
    for all s in S:
        V(s) <- max_{a} sum_{s'} p(s'|s,a) [r(s,a,s') + gamma*V(s')]
until V converged

pi*(s) = argmax_a sum_{s'} p(s'|s,a) [r(s,a,s') + gamma*V*(s')]
```

### GridWorld Example ($\gamma=1$, step cost $=-5$)
![[Lec11_Pg047_Gridworld_Example_Gamma_1_Step_Cost.png]]


4×4 grid: goal $+100$, trap $-100$, step cost $-5$. Deterministic transitions.

| Iteration | Effect                                                             |
| --------- | ------------------------------------------------------------------ |
| 0         | All $V(s) = 0$                                                     |
| 1         | Goal gets $+100$, trap gets $-100$. Adjacent cells update.         |
| 2–5       | Values propagate outward from goal and trap.                       |
| 6         | Convergence — no further change. Greedy policy gives optimal path. |

> **Intuition**: value iteration "floods" the grid outward from the goal and trap. States close to the goal converge first; farther states feel the reward signal later.

### Pros and Cons of Dynamic Programming
![[Lec11_Pg056_Pros_And_Cons_Of_Dynamic_Programming.png]]


|                                                                             |     |
| --------------------------------------------------------------------------- | --- |
| ✅ Exact — guaranteed convergence to $\pi^*$                                |     |
| ✅ Value iteration more efficient than policy iteration                     |     |
| ❌ Requires full model $p(s' \mid s,a)$                                     |     |
| ❌ Must iterate over all $s \in S$ — infeasible for large/continuous spaces |     |
| ❌ Memory proportional to $\lvert S \rvert$                                 |     |

> When state space is too large → **Temporal-Difference** learning.

## Temporal-Difference (TD) Learning

### Core Idea
![[Lec11_Pg059_Core_Idea.png]]


Only update **visited states**. Use **bootstrapping**: use current value estimates as targets without waiting for the episode to end.

For each step from $s$ via action $a$ to $s'$:
$$\Delta V(s) = \underbrace{r(s,a) + \gamma V(s')}_{\text{TD target}} - V(s) \qquad (\text{TD error})$$
$$V(s) \leftarrow V(s) + \alpha\, \Delta V(s), \quad \alpha > 0$$

### Exploration vs. Exploitation
![[Lec11_Pg061_Exploration_Vs_Exploitation.png]]


| Strategy                       | Description                                       | Drawback                          |
| ------------------------------ | ------------------------------------------------- | --------------------------------- |
| **Random** (pure exploration)  | Choose randomly every step                        | Wastes effort on known bad states |
| **Greedy** (pure exploitation) | Always take highest-Q action                      | Gets stuck in local optima        |
| **$\varepsilon$-greedy**       | Random with prob. $\varepsilon$; greedy otherwise | Good practical balance            |

$\varepsilon$ is typically annealed from $1.0$ down to a small value (e.g., $0.05$) over training.

### Two Major Implementations

#### SARSA (On-Policy TD)
![[Lec11_Pg063_Sarsa_On_Policy_Td.png]]


Uses the next action $a'$ actually taken by the **same policy**:

$$\Delta Q(s, a) = r_{t+1} + \gamma Q(s', a') - Q(s, a)$$
$$Q(s, a) \leftarrow Q(s, a) + \alpha\, \Delta Q(s, a)$$

**On-policy**: the data-collection policy = the policy being updated. Because SARSA factors in the actual (possibly random) next action, it tends to be **more cautious near dangerous states**.

> **Example**: Agent uses $\varepsilon$-greedy. In state $s'$ it randomly picks $a'$. SARSA updates $Q$ using that random $a'$, learning the value of the $\varepsilon$-greedy policy itself — not the optimal one.

#### Q-Learning (Off-Policy TD)
![[Lec11_Pg064_Q_Learning_Off_Policy_Td.png]]


Uses the **best possible** next action regardless of what the exploration policy would take:

$$\Delta Q(s, a) = r_{t+1} + \gamma \max_{a'} Q(s', a') - Q(s, a)$$
$$Q(s, a) \leftarrow Q(s, a) + \alpha\, \Delta Q(s, a)$$

**Off-policy**: data collected via $\varepsilon$-greedy, but updates use the greedy max — converges directly to $Q^*$.

**SARSA vs. Q-Learning:**

|                | SARSA                            | Q-Learning                           |
| -------------- | -------------------------------- | ------------------------------------ |
| Type           | On-policy                        | Off-policy                           |
| Update target  | $Q(s', a')$ — actual next action | $\max_{a'} Q(s',a')$ — best possible |
| Converges to   | $Q^{\varepsilon\text{-greedy}}$  | $Q^*$                                |
| Risk behaviour | Cautious near danger             | More aggressive during training      |

#### Worked Example: Q-Learning ($\gamma=1$, step cost $=0$, $\alpha=0.1$)

```
3x3 GridWorld. Goal at (2,2): reward +1. All Q = 0 initially.

Episode 1:
  s=(0,0), random "right" -> s'=(0,1), r=0
  DeltaQ = 0 + 1.0 * max Q(0,1,.) - 0 = 0   [no update yet]

Episode 2:
  ... -> s=(1,2) "down" -> s'=(2,2), r=+1  (goal!)
  DeltaQ[(1,2), down] = 1 + 0 - 0 = 1.0
  Q[(1,2), down] <- 0 + 0.1 * 1.0 = 0.1

Episode 3:
  s=(0,2) "down" -> s'=(1,2)
  DeltaQ[(0,2), down] = 0 + 1.0 * 0.1 - 0 = 0.1
  Q[(0,2), down] <- 0 + 0.1 * 0.1 = 0.01

After many episodes: Q-values converge; greedy policy traces shortest path to goal.
```

### TD Learning: Pros and Cons
![[Lec11_Pg070_Td_Learning_Pros_And_Cons.png]]


|                                                        |     |
| ------------------------------------------------------ | --- |
| ✅ No model needed — does not require $p(s' \mid s,a)$ |     |
| ✅ Online updates — learn after every step             |     |
| ✅ Lower variance than full Monte-Carlo                |     |
| ❌ Biased — bootstrapping introduces bias              |     |
| ❌ Exploration vs. exploitation dilemma                |     |
| ❌ Can behave poorly in stochastic environments        |     |

## Deep Reinforcement Learning

### Motivation: Tabular Methods Fail at Scale
- Learn each $(s,a)$ pair independently — **no generalisation**
- For raw image inputs (e.g., Atari frames), $|S|$ is astronomically large → Q-table impossible to store

**Solution**: approximate $Q(s,a)$ or $\pi(a|s)$ with a **neural network**.

---

### Deep Q-Networks (DQN)
![[Lec11_Pg074_Deep_Q_Networks_Dqn.png]]


Use a neural network $Q_\theta(s,a) \approx Q^*(s,a)$. The Q-learning update becomes **SGD** on:

$$\mathcal{L}(\theta) = \mathbb{E}\!\left[\left(y - Q_\theta(s,a)\right)^2\right], \quad y = r + \gamma \max_{a'} Q_{\bar\theta}(s',a')$$

- $\bar\theta$ = **target network** (frozen copy of $\theta$, periodically synced for stability)

#### Experience Replay
![[Lec11_Pg076_Experience_Replay.png]]


**Problem**: consecutive transitions are strongly correlated — violates SGD's i.i.d. assumption.

**Solution**: store transitions in a **replay buffer**, sample random mini-batches for updates.

```
Run eps-greedy -> store (s, a, r, s') in Replay Buffer
                              |
                   Sample i.i.d. mini-batch
                              |
            Update Q-network via SGD on
        (r + gamma * max_{a'} Q_tbar(s',a') - Q_t(s,a))^2
```

Q-learning is off-policy → old buffer samples remain valid.

#### DQN Architecture (Atari)
```
Input: 4 stacked grayscale frames (84x84x4)
  -> Conv(8x8, 32 filters, stride=4) -> ReLU
  -> Conv(4x4, 64 filters, stride=2) -> ReLU
  -> Conv(3x3, 64 filters, stride=1) -> ReLU
  -> Flatten -> Dense(512) -> ReLU
  -> Dense(num_actions)    <- one Q-value per discrete action
```

**Achievement**: Mnih et al. [2013] reached superhuman performance on many Atari games from raw pixels using the same architecture and hyperparameters across all games.

#### DQN Key Tricks
![[Lec11_Pg076_Dqn_Key_Tricks.png]]


| Trick                               | Why                                                        |
| ----------------------------------- | ---------------------------------------------------------- |
| **Experience Replay**               | Break temporal correlations; reuse transitions efficiently |
| **Target Network** $Q_{\bar\theta}$ | Stable training targets; prevent oscillations              |
| **ε-greedy**                        | Balance exploration/exploitation during training           |

**Limitation**: DQN requires a **discrete** action space (one Q-value output per action).

### Policy Gradient Methods
Instead of learning $Q$ and deriving $\pi$, **directly optimise $\pi_\theta$** by gradient ascent on expected return.

#### Policy Evaluation
![[Lec11_Pg079_Policy_Evaluation.png]]


A **trajectory** $\tau = (s_1, a_1, \ldots, s_T, a_T)$ is sampled from:

$$p_\theta(\tau) = p(s_1) \prod_{t=1}^T \pi_\theta(a_t|s_t)\, p(s_{t+1}|a_t, s_t)$$

**Performance measure**: $J(\theta) = \mathbb{E}_{\tau \sim p_\theta(\tau)}\!\left[\sum_t \gamma^t r(s_t, a_t)\right]$

**Objective**: $\theta^* = \arg\max_\theta J(\theta)$, updated via $\theta \leftarrow \theta + \nabla_\theta J(\theta)$.

#### Policy Gradient Derivation
![[Lec11_Pg085_Policy_Gradient_Derivation.png]]


$$\nabla_\theta J(\theta) = \nabla_\theta \int p_\theta(\tau)\, r(\tau)\, d\tau = \mathbb{E}_{\tau \sim p_\theta(\tau)}\!\left[\nabla_\theta \log p_\theta(\tau)\, r(\tau)\right]$$

Since transition dynamics are independent of $\theta$:
$$\nabla_\theta \log p_\theta(\tau) = \sum_{t=1}^T \nabla_\theta \log \pi_\theta(a_t|s_t)$$

**Policy gradient theorem**:
$$\boxed{\nabla_\theta J(\theta) = \mathbb{E}_{\tau \sim p_\theta(\tau)}\!\left[\sum_{t=1}^T \nabla_\theta \log \pi_\theta(a_t|s_t) \cdot r(\tau)\right]}$$

> **Key property**: no knowledge of environment dynamics needed — only the policy and sampled rewards.

---

### REINFORCE (Monte-Carlo Policy Gradient)
![[Lec11_Pg086_Reinforce_Monte_Carlo_Policy_Gradient.png]]


Sample $N$ full trajectory rollouts then update:

$$\nabla_\theta J(\theta) \approx \frac{1}{N} \sum_i \left(\sum_{t=0}^T \nabla_\theta \log \pi_\theta(a_t^i|s_t^i)\right)\!\left(\sum_{t=0}^T \gamma^t r(s_t^i, a_t^i)\right)$$

$$\theta \leftarrow \theta + \alpha\, \nabla_\theta J(\theta)$$

Must complete **full episodes** before updating.

> **Intuition**: high-return trajectories get their action probabilities boosted; bad ones are suppressed. _"If it worked, do more of it."_

#### Variance Problem and Baseline
![[Lec11_Pg088_Variance_Problem_And_Baseline.png]]


Monte-Carlo sampling → **noisy gradients** (few samples, high variance).

**Fix**: subtract a **baseline** $b(s_t)$ that is independent of $a_t$ (keeps gradient unbiased):

$$\nabla_\theta J(\theta) \approx \frac{1}{N} \sum_i \sum_t \nabla_\theta \log \pi_\theta(a_t^i|s_t^i)\!\left(\sum_{t'} \gamma^{t'} r_{t'}^i - b(s_t^i)\right)$$

Common choices:

- **Average reward** across the batch
- **State-value function** $V(s_t)$ → advantage $A_t = G_t - V(s_t)$

---

### Actor-Critic
![[Lec11_Pg090_Actor_Critic.png]]


Reduce variance further (with some bias) by using **bootstrapping** instead of full returns:

$$\nabla_\theta J(\theta) \approx \frac{1}{N} \sum_i \sum_t \nabla_\theta \log \pi_\theta(a_t^i|s_t^i) \underbrace{\bigl(r(s_t^i, a_t^i) + \gamma V(s_{t+1}^i) - V(s_t^i)\bigr)}_{\hat{A}_t = \text{ estimated advantage (TD error)}}$$

This is the **advantage function** with a bootstrapped estimate:
$$A_t = Q(s_t, a_t) - V(s_t) \approx r(s_t, a_t) + \gamma V(s_{t+1}) - V(s_t) = \hat{A}_t$$

**Architecture**:

```
        State s
          |
   +------+------+
   |             |
 Actor         Critic
(pi_theta)    (V_phi)
 a ~ pi(.|s)   V(s)  ->  compute A_hat_t
```

- **Actor**: policy network $\pi_\theta$, updated by gradient ascent using $\hat{A}_t$
- **Critic**: value network $V_\phi$, updated by minimising $(r + \gamma V(s') - V(s))^2$

**Most SOTA RL algorithms build on actor-critic.**

---

### Why Vanilla Actor-Critic is Fragile
![[Lec11_Pg094_Why_Vanilla_Actor_Critic_Is_Fragile.png]]


In **supervised learning**: data distribution is fixed.

In **RL**: the policy _defines_ the data distribution:

- A policy update changes which actions are taken → which states are visited → which data is seen next

> **Small parameter change ⟹ potentially huge behaviour change**

A single large update can completely collapse the training distribution.

---

### Trust Region Policy Optimisation (TRPO)
![[Lec11_Pg096_Trust_Region_Policy_Optimisation_Trpo.png]]


Step size is much harder to tune in RL than in SL:

- Too small → slow learning
- Too large → catastrophic collapse

**TRPO** [Schulman et al., 2015]: optimise a **surrogate objective** using old-policy data, constrained by a hard **KL divergence** limit:

$$\max_\theta \; \mathbb{E}_t\!\left[\frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_\text{old}}(a_t|s_t)} \hat{A}_t\right] \quad \text{s.t.} \quad \mathbb{E}_t\!\left[D_\text{KL}\!\left(\pi_{\theta_\text{old}}(\cdot|s_t) \,\|\, \pi_\theta(\cdot|s_t)\right)\right] \leq \delta$$

- **Probability ratio**: importance sampling correction for using old-policy data
- **KL constraint**: keeps the update inside a "trust region"
- Solved via Fisher Information Matrix + conjugate gradient — **second-order** method (expensive)

---

### Proximal Policy Optimisation (PPO)
![[Lec11_Pg102_Proximal_Policy_Optimisation_Ppo.png]]


**PPO** [Schulman et al., 2017]: the practical successor to TRPO.

#### Step 1: KL Penalty (Soft Constraint)

Replace the hard constraint with a tunable **penalty**:

$$\max_\theta \; \mathbb{E}_t\!\left[\frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_\text{old}}(a_t|s_t)} \hat{A}_t\right] - \beta \cdot \mathbb{E}_t\!\left[D_\text{KL}\!\left(\pi_{\theta_\text{old}}(\cdot|s_t) \,\|\, \pi_\theta(\cdot|s_t)\right)\right]$$

#### Step 2: Clipped Objective (PPO-CLIP) — the standard version
![[Lec11_Pg099_Step_2_Clipped_Objective_Ppo_Clip.png]]


**Clip the probability ratio** directly:

$$\mathcal{L}^\text{CLIP}(\theta) = \mathbb{E}_t\!\left[\min\!\left(r_t(\theta)\hat{A}_t,\ \operatorname{clip}(r_t(\theta),\, 1-\varepsilon,\, 1+\varepsilon)\hat{A}_t\right)\right]$$

where $r_t(\theta) = \dfrac{\pi_\theta(a_t|s_t)}{\pi_{\theta_\text{old}}(a_t|s_t)}$

**Clipping mechanics** (typical $\varepsilon = 0.2$, clip range $[0.8, 1.2]$):

| Scenario                              | Effect                                    |
| ------------------------------------- | ----------------------------------------- |
| $\hat{A}_t > 0$, $r_t > 1.2$          | Clipped — no gradient for pushing further |
| $\hat{A}_t > 0$, $r_t \in [0.8, 1.2]$ | Normal gradient ascent                    |
| $\hat{A}_t < 0$, $r_t < 0.8$          | Clipped — no gradient for pushing further |
| $\hat{A}_t < 0$, $r_t \in [0.8, 1.2]$ | Normal gradient descent                   |

> **Intuition**: The $\min$ ensures we never benefit from pushing the ratio outside $[1-\varepsilon, 1+\varepsilon]$ — the gradient becomes zero if the policy moves too far.

**Worked Example** ($\varepsilon = 0.2$):

```
Action a in state s, advantage A_hat = +2.0 (good action)
  pi_old(a|s) = 0.30
  pi_new(a|s) = 0.45  ->  ratio = 0.45/0.30 = 1.50

  Without clipping:  L = 1.50 * 2.0 = 3.0
  With clip(1.50, 0.8, 1.2) = 1.2:
    L = min(1.50*2.0, 1.2*2.0) = min(3.0, 2.4) = 2.4

  Update is capped — cannot become too aggressive even for a very good action.
```

#### PPO vs. TRPO
![[Lec11_Pg104_Ppo_Vs_Trpo.png]]


| Property                  | TRPO                              | PPO                  |
| ------------------------- | --------------------------------- | -------------------- |
| Constraint                | Hard KL                           | Clipped ratio        |
| Optimisation order        | Second-order (conjugate gradient) | First-order (Adam)   |
| Implementation complexity | High                              | Low                  |
| Computation cost          | Heavy                             | Lightweight          |
| Performance               | Good                              | Comparable or better |

## Reinforcement Learning from Human Feedback (RLHF)

Large language models are initially trained with **next-token prediction**, which teaches them to model text distributions well. But this objective does **not** directly optimise for what humans actually want: helpfulness, harmlessness, honesty, instruction-following, or style preferences. RLHF addresses this gap by turning human preferences into a learning signal (Ouyang et al., 2022).

### Three-Stage Pipeline

#### 1. Supervised Fine-Tuning (SFT)

Start from a pre-trained language model and fine-tune it on **human-written demonstrations** of good behaviour.

- Input: prompt $x$
- Target: high-quality human response $y$
- Result: a model that can follow instructions reasonably well

#### 2. Reward Model Training

Next, collect **human preference comparisons**. Annotators are shown two candidate responses for the same prompt and choose the better one.

If $y_w$ is the preferred response and $y_l$ the rejected one, the reward model $r_\phi$ is trained so that

$$
r_\phi(x, y_w) > r_\phi(x, y_l)
$$

A common pairwise objective is

$$
\mathcal{L}_\text{RM} = -\log \sigma\!\left(r_\phi(x, y_w) - r_\phi(x, y_l)\right)
$$

so the reward model learns to approximate **human preference**.

#### 3. RL Fine-Tuning with PPO

Finally, optimise the policy against the reward model using [PPO](#proximal-policy-optimisation-ppo). The objective is not just "maximise reward", but "maximise reward while staying close to the reference model":

$$
\max_\theta \;\mathbb{E}_{y \sim \pi_\theta(\cdot|x)}\!\left[r_\phi(x, y)\right]
\;-\;
\beta\, D_\text{KL}\!\left(\pi_\theta(\cdot|x)\,\|\,\pi_\text{ref}(\cdot|x)\right)
$$

where:

- $\pi_\theta$ is the current policy
- $\pi_\text{ref}$ is usually the SFT model
- $r_\phi$ is the learned reward model
- $\beta$ controls how strongly we penalise deviation from the reference model

### Why the KL Penalty Matters

Without the KL term, the model may exploit weaknesses in the reward model and drift toward unnatural text. This is a form of **reward hacking**.

The KL penalty helps because it:

- keeps the policy close to the original language model
- preserves fluency and general language competence
- prevents the model from chasing spurious high-reward behaviours too aggressively

> **Example**: A reward model might accidentally prefer overly long, overly flattering, or repetitive answers. Without a KL penalty, the policy could exploit this artifact instead of becoming genuinely more helpful.

### RLHF in One Picture

| Stage            | Data source                              | Objective                                   |
| ---------------- | ---------------------------------------- | ------------------------------------------- |
| **SFT**          | Human demonstrations                     | Learn to imitate good answers               |
| **Reward model** | Human preference comparisons             | Learn a scalar proxy for human judgement    |
| **RL with PPO**  | Model-generated responses + reward model | Optimise policy while constraining KL drift |

In short, RLHF combines **supervised learning**, **preference modelling**, and **reinforcement learning**. In practice, the RL stage is usually performed with **PPO**, which is why PPO became central to instruction-tuning pipelines such as InstructGPT (Ouyang et al., 2022).

## Summary

### Algorithms

| Algorithm            | Family               | Key Idea                                                        |
| -------------------- | -------------------- | --------------------------------------------------------------- |
| **Value Iteration**  | DP                   | Bellman optimality as iterative update; full model required     |
| **Policy Iteration** | DP                   | Alternate policy eval + greedy improvement; full model required |
| **SARSA**            | TD, on-policy        | Q updates using actual next action from same policy             |
| **Q-Learning**       | TD, off-policy       | Q updates using greedy max; converges to $Q^*$                  |
| **DQN**              | Deep value-based     | Neural Q-function + experience replay + target network          |
| **REINFORCE**        | Policy gradient (MC) | Full trajectory rollouts; high variance                         |
| **Actor-Critic**     | Policy gradient + TD | TD-error as advantage; bootstrapped; lower variance             |
| **TRPO**             | Actor-Critic         | Hard KL trust region; second-order optimisation                 |
| **PPO**              | Actor-Critic         | Clipped ratio; first-order; most widely used                    |

### Key Concepts
![[Lec11_Pg045_Key_Concepts.png]]


| Concept                 | One-line summary                                                 |
| ----------------------- | ---------------------------------------------------------------- |
| MDP                     | Formal framework: $(S,A,R,T,\mu)$                                |
| Bellman equation        | $V(s)$ = immediate reward + discounted value of next state       |
| Bootstrapping           | Use current value estimate as target; update before episode ends |
| On-policy vs off-policy | Same vs different policy for data collection and updates         |
| Advantage $\hat{A}_t$   | How much better action $a$ is vs average: $Q(s,a)-V(s)$          |
| Trust region            | Constrain policy updates to stay close to old policy             |
